# OFFSCRPT V90.0.0 — RAZORPAY PAYMENTS + UPI-FIRST CHECKOUT

## Scope
V90 replaces the V89 simulated payment boundary with Razorpay Standard Checkout and server-authoritative verification. Existing `commerceProducts`, `commercePrices`, `commerceOrders`, `commercePayments`, `entitlements`, `creatorRevenue`, and private R2 delivery remain canonical.

## Payment flow
1. Authenticated buyer selects an active public product.
2. Server loads the canonical product and active one-time price.
3. Server checks existing entitlement and rejects unnecessary duplicate purchases.
4. Server creates an OFFSCRPT `commerceOrders` record and `commercePayments` record.
5. Server creates a Razorpay Order using the canonical amount in currency subunits.
6. Browser receives only safe Checkout configuration including the public Razorpay Key ID and provider Order ID.
7. Razorpay Checkout handles UPI-first payment UX plus other enabled methods.
8. Razorpay returns payment identifiers to the handler callback.
9. Server verifies the callback signature using the canonical server-stored Razorpay Order ID and Key Secret.
10. Server fetches/validates the Razorpay Payment and requires the captured state.
11. Server verifies amount, currency, provider Order ID and OFFSCRPT order linkage.
12. Server idempotently marks the canonical payment/order paid and creates the existing entitlement.
13. Razorpay webhook processing independently verifies webhook signatures and handles `payment.captured`, with replay-safe event storage.
14. Existing My Purchases and secure R2 download behavior are unchanged.

## Environment variables
Configure on the server only:
- `RAZORPAY_KEY_ID`
- `RAZORPAY_KEY_SECRET`
- `RAZORPAY_ENVIRONMENT`
- `RAZORPAY_API_VERSION` (optional metadata/version pin if used)
- `RAZORPAY_WEBHOOK_SECRET`
- `OFFSCRPT_PRODUCTION_URL`

Use Razorpay Test Mode for development/preview and Live Mode only in production. Never put `RAZORPAY_KEY_SECRET` or `RAZORPAY_WEBHOOK_SECRET` in frontend variables, `src`, `public`, fixtures, or documentation.

## Razorpay Dashboard
Configure a webhook pointing to:
`https://offscrpt.vercel.app/api/commerce?action=razorpayWebhook`
(or the final canonical production domain/path selected during deployment).

Enable the payment/refund event set required by V90. The implementation treats `payment.captured` as the successful payment event; unknown events are acknowledged without inventing a paid state.

## Production checklist
- Razorpay Live credentials configured in Vercel Production.
- Razorpay webhook secret configured.
- Production webhook URL points to the canonical domain.
- Test-mode fake purchase path is absent from ordinary buyer UI.
- `npm run check:v90-razorpay-payments`
- `npm run typecheck`
- `npm run lint`
- `npm run build`
- Run the complete V90 mobile, desktop, duplicate webhook, amount mismatch, pending, failed, cancellation, browser-close, cross-account and R2 download tests.
