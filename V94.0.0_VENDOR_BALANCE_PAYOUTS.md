# OFFSCRPT V94.0.0 — Vendor Balance + Payouts

V94 consumes V93 financial allocations into an append-only creator ledger, pending/available/reserved balances, idempotent payout requests, Razorpay Route direct transfers, verified transfer webhooks, reconciliation, failure/reversal handling, creator payout UI, and Master Admin payout operations.

## Defaults
- Hold period: 7 days unless `siteConfig/global.commercePayouts.payoutHoldDays` overrides it.
- Minimum payout: ₹100 unless `siteConfig/global.commercePayouts.minimumPayoutAmountPaise` overrides it.
- Manual review: enabled by default.

## Provider
Razorpay Route direct transfers are server-side only and require Route activation on the Razorpay merchant account. V94 must fail closed when Route is unavailable.

## Collections
- `commerceVendorLedger` — append-only financial movements.
- `creatorCommerceBalances` — cached/versioned balance snapshot; ledger remains the source for reconstruction.
- `creatorPayouts` — payout lifecycle records.

## Route webhook
Existing `/api/commerce?action=razorpayRouteWebhook` handles transfer processed/failed/reversal events. The implementation reconciles the transfer `recipient` against the canonical seller `razorpayAccountId`; the webhook's top-level `account_id` is treated as provider context.

## Security
Creator IDs, seller IDs, provider account IDs, balances, payout amounts, statuses and transfer IDs are server-authoritative. Direct Firestore client writes to ledger/balances/payout state are denied.

## Known external prerequisite
Razorpay Route Direct Transfers are an on-demand feature; the merchant account must have Route transfer capability activated before live payout execution can succeed.
