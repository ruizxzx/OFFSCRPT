# OFFSCRPT V96.0.7 — Firestore Query Index Hotfix

## Problem
Product pages could fail when the deployed Firestore index set did not contain V96's multi-filter review and creator-product composites.

## Fix
- Public review reads no longer require `moderationStatus` as a Firestore filter; it is enforced server-side after querying the established `productId + status + createdAt/rating/verifiedPurchase` indexes.
- Creator trust reads no longer require `status + visibility` in the Firestore query; those values are filtered server-side after the established `creatorId + updatedAt` index query.
- Own-review lookup no longer requires `reviewerId + productId + updatedAt`; product filtering is performed server-side.
- Added missing `reviewerId + createdAt` and `reporterId + createdAt` indexes for abuse-limit queries.
- Retained/added the exact composites shown by the Firebase error as deployment-safe compatibility indexes.

## Result
The product page no longer depends on the two composites shown in the reported 400 FAILED_PRECONDITION errors for its normal public review and trust requests.
