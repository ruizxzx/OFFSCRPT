# OFFSCRPT V96.0.6 — FIXED BUILD AUDIT

This build is based on the supplied OFFSCRPT V96.0.0 archive and rechecked against the V96 Trust, Moderation, Reviews & Marketplace Safety specification.

## Fixes verified in this build

- V96 Firestore document-path whitelist includes all implemented trust/moderation collections.
- Review creation, editing, removal, moderation and aggregate mutations use atomic commits with state preconditions where required.
- Review purchase eligibility is derived from canonical Commerce orders; creator self-review is rejected; client verification fields are not authoritative.
- Review pagination uses stable server cursors and de-duplicates inclusive cursor boundaries.
- Buyer review lookup can be scoped to the current product so older reviews do not hide edit/remove controls.
- Review creation has a bounded server-side daily abuse limit.
- Report submission validates order ownership, suppresses same-user duplicate reports, and atomically updates linked review/case/aggregate state.
- Moderation queue pagination is server-side and cursor-safe.
- Moderation permissions support both array and boolean-map representations.
- Moderator assignment accepts both explicit master-admin documents and users carrying the master-admin platform role.
- Moderation target/case binding is validated server-side.
- Product and creator moderation actions resolve their linked case and reports atomically when a case is supplied.
- Review moderation state changes synchronize linked case/report state and aggregate contributions.
- Trust Health scans complete paginated collections and checks review, report, case, action, audit, aggregate and orphan integrity.
- Aggregate validation/rebuild includes rating totals and produces explicit audited repairs only.
- Public review projection does not expose reviewer UID or order/payment identifiers.
- Admin case detail uses an admin-safe projection so authorized moderators retain necessary reviewer/order/product context without exposing unrelated private fields.
- Product/creator trust signals respect seller enablement and onboarding state.
- Historical V95 finance reporting includes refunded and partially-refunded orders and uses complete server-side pagination for the affected datasets.
- Public creator trust uses complete product traversal rather than a 100-product cap.
- Fixed the missing `getPublicCreatorTrustSignals` import in `CreatorView`.
- Rebuilt the Trust & Moderation admin JSX after a structural JSX defect was detected.
- Added review pagination UI (`LOAD MORE REVIEWS`) so the implemented server cursor is reachable by buyers.
